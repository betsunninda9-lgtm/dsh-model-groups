# 供应商编辑器接口：提案与本机试用记录

状态：`0.4.0-alpha.13` 已完成可选统一编辑器，并在用户确认试修后进行了一次可逆本机接口接入；安装插件本身不会应用该宿主改动。原生文件与配置备份位于本机私有的 `dsh-model-groups/editor-interface-trial-20261119/`。本机最终已认证页面仍须刷新后验收，不能用隔离截图替代。

## 已确认的问题

早期版本曾把独立编辑器注册到 `settings.models.provider-card`，而原生供应商的“编辑”按钮只控制原生 `ProviderEditor`，因此出现两个独立表单与两组“保存／取消”。早期界面还无条件显示共用配置，使未启用多密钥的供应商也有额外表单。当前 alpha.14 已改为下述可选接口接入，无接口时只显示页尾限制说明。

迁移前已存在的不同供应商不能按相似显示名称删除。应消除重复编辑器，而不是删除供应商或密钥。

整页替换已被前置验证否决：原页面拥有第三方卡片和页尾的子插槽，替换页面不能合法代为渲染这些插槽。该路线没有实施。

## 最小宿主接口建议

由原生 Models 页面额外声明 `settings.models.provider-editor`，类型为 `keyed`、作用域为 `root`，按 `settingsNs` 匹配编辑器。页面、账户区、第三方 provider-card 与 footer 的所有权仍归原生页面。

原页面传给新编辑器的属性：

| 属性 | 作用 |
| --- | --- |
| `provider` | 原有供应商目录身份；稳定 Provider ID 不变 |
| `configured` / `keyConfigured` | 已有配置与凭据状态 |
| `open` | 原生“编辑”按钮控制的展开状态 |
| `readOnly` | 原页面权限状态，插件必须同步遵守 |
| `defaultEditor` | 原生单密钥编辑器的 React 节点；未接管的供应商直接返回它 |
| `onClose(changed)` | 关闭原生编辑状态，必要时刷新标题与保存提示 |

插件只在新插槽注册编辑器，不再在 provider-card 插槽放第二套编辑表单。`llm-pi-ai` 供应商的单密钥、多密钥、名称和连接设置共用一份草稿；其他命名空间与没有注册者的接口继续使用 `defaultEditor`。同一供应商在任一时刻只能有一套编辑器。

原页面用自己的 `hidden` 容器统一收起整个编辑区域。插件组件在供应商折叠时保持挂载，草稿与密钥输入仅留在内存；不通过折叠触发保存。这里的容器属于原生页面本身，不是插件遍历或隐藏其他插件的 DOM。

新插槽没有注册者时，仍回退到原生编辑器。删除新编辑器注册不会移除模型页、账户区或其他插件的扩展，也不会取得这些子插槽的权限。

## 原型范围与验证

`test/prototypes/provider-editor-seam.mjs` 只接收调用方传入的源代码副本，返回提议的副本；没有文件访问、安装、自动应用或运行时补丁功能。当前只针对本次检查过的原生模块验证接口建议，不宣称它是兼容任意构建的修改器。

`test/provider-editor-seam.test.mjs` 使用实际公开 SlotCore 与当前 Renderer 的内存副本验证：页面保持原所有者；新编辑器可以由原页面渲染；第三方卡片和页尾保留；编辑器不能窃取这些插槽的权限；撤销编辑器后原页面仍在。

`test/browser/provider-editor-seam.mjs` 使用真实 Chromium、原生完整 `Loaded` 模型页与 `ProviderEditor`、当前多密钥组件以及公开 SlotCore。Settings、凭据和数据为测试夹具，插槽组合在浏览器测试中模拟；它不是实际登录本机 GUI 的端到端验收。验证 390 / 860 宽度下的整组折叠、未保存草稿保留、每供应商一套表单、普通供应商无多余共用配置、只读状态、账户及第三方扩展保留、撤销编辑器后的原生回退。测试禁止用户配置、凭据与网络写入，并核对真实宿主模块未被改动。

## 兼容边界与本机试用

用户在了解接口缺失及其他移植版的降级限制后同意试修。本机只为这一轮试用新增编辑接口，先备份原文件，再通过插件管理器重新加载原生模型页和试用插件；没有恢复旧的五处业务补丁，也没有重启引擎。其他移植版无接口时仅显示页尾限制说明，已有分组与执行路径独立保留；不能把这次本机修改宣传成通用免补丁的完整编辑方案。

alpha.13 已实现供应商显示名、共用字段、原单密钥与密钥分组的一份草稿／基线，语义脏状态、统一保存／取消、模式切换及异步折叠保护。alpha.14 恢复公共设置与密钥卡片的父子层级，并作为独立 GitHub 分支预发布；该发布不包含本机宿主改动或私有备份。完整界面仍须在各设备的实际页面验收。

隔离测试需要未接入接口的基准。试用后可通过 `DSH_MODELS_CLIENT` 指向私有备份的 `settings-models.client.before.js`，避免把已经接入接口的本机文件再次当作未修改基准。该变量只供开发测试，不参与生产加载。
